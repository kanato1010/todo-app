# TODO App
シンプルなCLI TODOアプリ。dict/list版とclass版の2種類を実装し、設計の違いを比較。

## 機能
- タスクの追加/削除/完了切り替え
- JSON形式でのデータ永続化
- 入力エラー・範囲外アクセスのハンドリング

## 使い方
\`\`\`bash
python3 src/todo_dict.py   # dict/list版
python3 src/todo_class.py  # class版
\`\`\`

## dict/list版 vs class版
| 観点 | dict/list版 | class版 |
|---|---|---|
| データの持ち方 | `{"tasks": "牛乳買う", "done": False}` | `TodoItem("牛乳買う", False)` |
| 操作の書き方 | `todos[i]["done"] = not todos[i]["done"]` | `todos[i].toggle()` |
| 状態変更の意味 | 呼び出し側が「何をどう書き換えるか」を毎回知ってる必要がある | 「toggleする」という意図だけ書けば済む、中身の実装はTodoItem側に隠れてる |
| 保存/読み込み | そのまま`json.dump`/`json.load`できる(変換不要) | `to_dict`/`from_dict`という変換層が必要になる |
| タイポのリスク | `"tasks"`のようなキー名を毎回文字列で打つので、タイポしても実行時までエラーに気づけない | `.task`のように属性でアクセスするので、エディタの補完が効きやすい |
| 手軽さ | 小規模なら圧倒的に手早い(定義不要ですぐ使える) | 定義の手間がある分、立ち上がりはやや重い |
## 学んだこと
classは主に直感的なわかりやすさにメリットがある。
はじめ、todosの中身を都度インスタンス化→dictに戻すような書き方をしてしまい、AIにそれではclass化の意味がないと指摘された。
起動時に一回だけインスタンス化をまとめgて行い、保存時にそれをまとめてdictに戻してjsonに保存という動きに直すことができた。
